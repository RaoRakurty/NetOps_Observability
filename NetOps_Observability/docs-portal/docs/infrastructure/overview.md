# Infrastructure

The **Infrastructure** section is your window into the device fleet — what you have, how it's doing, where it is, and how traffic gets there. Everything here is populated automatically once devices are [onboarded](/onboard-devices/overview).

## What's in it

| Feature | Console path | What it's for |
| --- | --- | --- |
| **Devices** | <kbd>Infrastructure → Devices</kbd> | The inventory: status, facts, sites, per‑device detail |
| **Device Monitoring** | <kbd>Infrastructure → Device Monitoring</kbd> | Per‑device health dashboards (CPU/memory/interfaces) |
| **Interface Performance** | <kbd>Infrastructure → Interface Performance</kbd> | Per‑interface throughput, utilization, errors |
| **Protocol Monitoring** | <kbd>Infrastructure → Protocol Monitoring</kbd> | BGP/OSPF/IS‑IS neighbor state and changes |
| **Troubleshooting** | <kbd>Infrastructure → Troubleshooting</kbd> | Focused views for chasing a problem device |
| **[Topology Canvas](/infrastructure/topology-canvas)** | <kbd>Infrastructure → Topology Canvas</kbd> | Live, evidence‑backed network graph |
| **[Device Geomap](/infrastructure/geomap)** | <kbd>Infrastructure → Device Geomap</kbd> | Devices on a geographic map |
| **Flow Trace** | <kbd>Infrastructure → Flow Trace</kbd> | Hop‑by‑hop active path measurement |
| **[WAN Interface Metrics](/infrastructure/wan-interface-metrics)** | <kbd>Infrastructure → WAN Interface Metrics</kbd> | Per‑WAN‑interface SLA + live throughput |
| **Tunnels** | <kbd>Infrastructure → Tunnels</kbd> | Overlay/VPN tunnel health |

## Typical flow

Start at **Devices** to confirm your fleet, drop into **Device Monitoring** / **Interface Performance** for health, use the **Topology Canvas** to see relationships, and **Flow Trace** / **WAN Interface Metrics** to understand paths and circuits.
