# September 2026

## New features

### Security section

Correlix gained a top-level **Security** section covering continuous threat and
exposure management: an Overview with the CTEM funnel and assessment coverage,
Exposures with facets and an inspector, Exposure Stories, Threat Detection,
Compliance, Detection Rules and Saved Views.

Where the design asked for data the platform cannot supply, the console shows a
coverage card or omits the panel. It does not show a placeholder number.

- **Where:** Security
- **API:** `/api/security/findings`, `/api/security/findings/{id}`,
  `/api/security/findings/facets`, `/api/security/findings/trend`,
  `/api/security/posture`, `/api/security/exposure-stories`,
  `/api/security/rules`, `/api/security/views`
- **Read next:** [Security](/security/overview)

### Security findings now emit

A per-tenant bounded worker runs hardening, advisory and threat detections on a
15-minute cadence and ships each finding through the bus to a per-tenant search
index. Hardening over a device with no readable configuration yields **Unknown
(unassessed)**, never Pass. An advisory feed that is provisioned and matches
nothing is genuinely clear; a feed that is unavailable is unassessed.

- **Flag:** `FEATURE_SECURITY_LANE`, default off. With the flag off no worker
  starts and neither lane route is registered, so both answer `404`. The
  findings read API stays registered either way and reports honestly that
  nothing has been assessed.
- **API:** `GET /api/security/lane/status`, `POST /api/security/scan`
  (`429` when a scan is already queued or running)
- **Read next:** [Run a security scan](/security/run-a-scan)

### Security is the fourth evidence class in correlation

Security findings ground into RCA through the generic evidence intake, with no
security-specific engine code. A security-only correlation object is at most
**suspected** until an independent measurement plane corroborates it.

- **Where:** the RCA workspace, as its own source class with seam,
  internet-facing and provider chips, and per-row rule fidelity badges
- **Read next:** [How root-cause analysis works](/investigate/rca-explained)

### Configuration backup and drift

Capture a device's running configuration over the SSH gateway, normalise it per
vendor, hash it, seal it per tenant and diff it against a golden baseline. A
named redaction rule list is applied to every API and diff read while the sealed
copy keeps the original. Drift state is `in_sync`, `changed`, `drifted` or
`unknown`, and a drift finding carries a diff summary only, never configuration
lines.

- **Flag:** `FEATURE_CONFIG_BACKUP`, default off
- **Where:** a device's **Configuration** tab, and Infrastructure → Config Drift
- **API:** `/api/devices/{id}/config/status|backup|versions|diff|golden`,
  `/api/config/drift`
- **Read next:** [Back up a device configuration](/security/config-backup)

### Packet capture

Run a bounded capture on one device interface. Every capture is limited to
60 seconds, 10,000 packets and 25 MiB, one per device at a time. The BPF filter
passes through an allowlist parser that re-renders it canonically, so the
caller's bytes never reach a device. Blobs are sealed at rest, and start, fetch
and download are audited as sensitive reads.

- **Flag:** `FEATURE_PACKET_CAPTURE`, default off
- **Where:** a device's **Packet capture** tab
- **API:** `/api/devices/{id}/pcap`, `…/{capture_id}`, `…/{capture_id}/download`
- **Read next:** [Capture packets on a device](/security/packet-capture)

### Investigation surface

Troubleshooting now opens on **Investigation**, with two entry points: one of
nine canonical workflows, or an open correlation case. A case shows the same
six-question RCA header the RCA workspace shows, so there is one verdict
vocabulary rather than two. A symptom shows a bisecting ladder whose rungs are
earned from lane state: physical, L2, IGP, BGP, path and seam, application,
logs.

Seven evidence lanes run in parallel, each naming the API it read. A lane
distinguishes *not connected* (the source was never wired) from *empty* (the
source is wired and was quiet), and never collapses the two.

- **Where:** Investigate → Troubleshooting
- **Read next:** [Investigate a symptom](/investigate/investigate-a-symptom)

### Protocol diagnostics for BGP, OSPF and IS-IS

A version-pinned matrix of 15 issues across the three protocols. Each issue
carries its symptoms, its per-vendor dialect coverage and a read-only command
bundle rendered in the device's own dialect. Analyze runs hand-authored failure
signatures over the captured text and returns a verdict, a likely cause and a
remediation, or an honest "no known signature matched" with the raw output
attached. Export assembles a redacted bundle for vendor support.

- **API:** `/api/troubleshoot/protocol-diagnostics/catalog|analyze|collect|export`
- **Read next:** [Diagnose a BGP, OSPF or IS-IS issue](/investigate/protocol-diagnostics)

### Live collection for protocol diagnostics

The collect step can now run an issue's read-only command bundle against one of
your own devices over SSH, with output redacted at capture. It uses a dedicated
least-privilege diagnostics identity, and falls back to the configuration-backup
capture account only when none of the three diagnostics variables is set. A
partially configured identity is a hard error, never a silent fallback onto a
different account.

- **Flag:** `FEATURE_PROTOCOL_DIAG_COLLECT`, default off. With the flag off,
  collect answers an honest `503` and you paste the output instead.
- **Read next:** [Collect diagnostics from a device](/investigate/collect-from-a-device)

### OSPF and IS-IS depth

Per-adjacency views, fleet roll-ups and per-device health for both IGPs, plus
LSDB size, areas, SPF runs and timers. Every response carries a coverage block
and a notes list. A source nothing collects is reported absent, with a note
naming why. It is never reported as zero and never as healthy.

- **API:** `/api/protocols/{ospf|isis}/{adjacencies|summary|health}`
- **Where:** Analytics → Protocol Monitoring
- **Read next:** [Check OSPF and IS-IS adjacency health](/investigate/igp-health)

### BGP depth: RPKI, geofeed, AS-path graph and a live feed

RPKI origin validation per watchlist prefix, where `unknown` can never become
`valid`. Geofeed discovery per RFC 9092 with a conservative RFC 8805 parse that
drops malformed rows rather than repairing them. An AS-path graph capped
deterministically at 500 edges, where an unreadable path token becomes a gap and
the path is dropped rather than spliced into a fabricated adjacency. A near-live
update feed held in a bounded per-tenant ring.

ASPA ships as an honest "no ASPA source configured" card, because no public
per-ASN source exists. A provider URL is pluggable.

- **Flag:** `FEATURE_BGP_LIVE_FEED`, default off, for the feed
- **API:** `/api/bgp/rpki`, `/api/bgp/aspa`, `/api/bgp/geofeed`,
  `/api/bgp/aspath-graph`, `/api/bgp/feed`
- **Read next:** [BGP operations](/bgp/overview)

### BMP receiver

A router can now push its Adj-RIB-In to Correlix over TCP (RFC 7854). Correlix
decodes IPv4 and IPv6 unicast; every other address family is counted as
unsupported rather than partially decoded. A session's tenant is stamped from
the inventory device its source address resolves to, and a source that resolves
to nothing is refused rather than stored without a tenant.

Every response says what it is: a bounded monitoring feed of recent updates, not
a converged RIB.

- **Flag:** `FEATURE_BMP`, default off. `BMP_LISTEN` defaults to `:11019`.
- **API:** `/api/bgp/bmp/sessions|updates|stats`
- **Read next:** [Receive BMP from a router](/bgp/bmp)

### BGP alerting, leak and hijack classification, and bogons

One classifier per watched prefix, over a closed set of incident classes:
`visibility_loss`, `origin_change`, `rpki_invalid`, `route_leak`, `bogon`,
`none`, `unknown`. Every path-derived class needs at least two distinct vantage
points, and a near miss is reported as `corroboration_shortfall` rather than
hidden. The leak heuristic runs only against a declared upstream set; with no
set it does not guess.

Bogons come from an embedded IANA and RFC special-purpose set plus the RFC 4291
undelegated-IPv6 rule, with an optional Team Cymru feed. A feed outage never
un-flags a prefix that was already flagged.

- **Flags:** `FEATURE_BGP_ALERTS` and `FEATURE_BGP_BOGON_FEED`, both default off
- **API:** `/api/bgp/alerts`, `/api/bgp/alerts/config`, `/api/bgp/bogons`
- **Where:** BGP Operations gains **Peers** and **Bogons** tabs
- **Read next:** [Configure BGP alerting](/bgp/alerting)

### Iris skills

Troubleshooting method now ships as data rather than as code. Thirteen skill
files describe when a method applies, which read-only tools to gather with, what
to look for and where to go next. The loader fails on any tool, argument or
target that does not exist, so a method can never claim a capability the
platform lacks.

- **Read next:** [Iris skills and chaining](/iris-ai/skills)

### Iris skill chaining

A turn now runs up to four rounds. The next skill is chosen first by authored
machine conditions from a closed vocabulary, then by a closed model choice among
that skill's own declared targets, validated server-side. Bounds are 6 tools per
round, 16 per turn and 45 seconds of wall clock. Every budget stop is disclosed
and lifted into the missing-evidence list.

### Iris reads live device state

Iris can run a per-vendor read-only state battery through the SSH runner under
the caller's tenant and parse it deterministically. An unparseable capture is
skipped with a reason, never turned into a fabricated field; unparsed text is
quoted, redacted and labelled. No transport, no write permission, an unresolvable
dialect or a failed run all return an honest "not wired" plus the read-only
command list.

### Investigation memory

Iris keeps one row per concluded investigation, written when an operator rates
an answer. Unjudged conclusions are forgotten after a bounded lifetime. Recall
returns at most five read-only rows, each carrying the outcome in operator words
and the rule to verify current state first. Memory is evidence, never a rule: it
cannot decide the next step.

- **Read next:** [Investigation memory](/iris-ai/memory)

### Six-question RCA header

The RCA header answers all six operator questions above the fold: what broke,
why Correlix believes that, what is affected, when, which evidence and which RCA
id. "Affected" is derived from the engine blast radius plus peer and application
impact, and renders **Not yet determined** rather than a bare zero.

- **Read next:** [Read an RCA case](/investigate/read-an-rca-case)

### Operator verdict feedback

Rate a verdict Correct, Partially or Wrong, with a five-word vocabulary for the
part that was wrong: cause, owner, affected, evidence, recovery. The 30-day tile
reads **Not enough feedback yet** on an empty sample rather than 0 %.

- **API:** `POST|GET /api/correlations/{id}/feedback`,
  `GET /api/correlations/feedback/summary`
- **Read next:** [Rate an RCA verdict](/investigate/rate-an-rca-case)

### Interfaces by routing instance

A per-device view of interfaces grouped by routing instance, in the device's own
dialect: VRF, routing-instance, VPRN or VPN instance. No interface series
carries a routing-instance label on either transport today, so the response
reports membership as not collected and returns the interfaces ungrouped with a
note. It never invents a "default" group. The label is probed on every request,
so grouping appears by itself the day a deployment collects it.

- **API:** `GET /api/devices/{id}/interfaces/by-vrf`
- **Read next:** [View interfaces by routing instance](/investigate/interfaces-by-routing-instance)

### Platform alerts reach the host-monitoring channel

Correlix's own health now pushes to the host-monitoring channel, so one phone
channel covers "the stack is sick". Only the server-controlled `page` tier
pages. The heartbeat is counted and never pushed. The push queue is bounded, so
a slow notification service cannot make the evaluator retry into a storm.

- **Env:** `PLATFORM_ALERTS_NTFY_TOPIC`, defaulting to `WATCHDOG_NTFY_TOPIC`
- **Read next:** [Built-in alert rules](/reference/alert-rules)

### Telemetry coverage

Parser revision and rules hash, semantic promotion rate, per-rule hit counts
with fidelity tiers, and the message shapes in your own tenant that the parser
would not admit, with read-only draft catalog rows. A draft applies nothing.

- **API:** `/api/admin/parser/stats` (platform admin),
  `/api/telemetry/unrecognized`, `…/{template_id}/propose`
- **Where:** Administration → Telemetry Coverage

### Deploy qualification

`scripts/deploy-qualify.sh` proves a deployment is doing work rather than merely
running. Phase 1 runs the bootstraps a fresh install needs. Phase 2 proves,
inside a bounded wait, that the engines joined their consumer groups, that lag
is draining rather than piling up, and that both ingest tiers are emitting.

- **Read next:** [Verify a deployment is doing work](/deploy/verify-deployment)

## Changes

- **Optional evidence lanes can no longer block the engine.** The correlation
  subscription is partitioned into 12 required lanes, which fail loudly and name
  the topic and the remedy, and optional evidence lanes, which are probed once
  after start, dropped and reported if absent, then re-probed every 90 seconds
  and re-subscribed in place. A lane enabled later grounds without a restart.
  `/healthz` now reports `degraded` with `health_reasons` when the supervisor is
  not consuming.
- **Engine-inferred recovery.** Recovery previously came from ticket facts only,
  so a deployment with no ticket link showed "not measured" forever. A closed
  correlation object with a window end now yields a `recovered` stamp marked
  `source=INFERRED`, with confidence capped at 0.7. Ticket facts still win when
  they exist.
- **Teams and Amazon SNS** became fully managed notification channels with
  severity floors and test buttons. Channel administration is restricted to the
  platform owner.
- **A device configuration-change symptom** now emits from SNMP traps on
  index-verified OIDs. The syslog counterpart ships in shadow, and shadow rules
  contribute nothing to the ingest screen.
- **Vendor profiles** became one embedded declarative profile per vendor and
  platform, covering detection, CLI dialect, capture commands, advisory binding,
  hardening binding and threat tags. Configuration capture and hardening were
  verified against live SR Linux and EOS devices.

## Removed

- The older Troubleshooting collection-pipeline board is removed, and with it
  the page's section switch — Troubleshooting is the investigation surface and
  nothing else. An old `?section=` deep link lands on it and the parameter is
  stripped from the address. The board's collector counts, per-collector rows
  and flow sources moved to **Platform → Tools → Stack Health** (Collection);
  its flow chips and trap pointer were already on Explore → Flows and
  Explore → Logs.

## Known limitations

- **OSPF depth is vendor-documented, not wire-confirmed.** The OSPF-MIB LSDB,
  area, SPF and timer reads are graded `doc_claimed`. No OSPF-speaking SNMP
  device exists in the validation lab. IS-IS depth over gNMI is graded
  `lab_validated` against live SR Linux.
- **Per-tenant compliance framework selection is not released yet.**
  `GET|PUT /api/security/frameworks` and `GET /api/security/compliance` are
  written but not yet in a shipped build. Until they land, the compliance
  scorecard is assessed against the shipped default set.
- **gNMI metrics reaching correlation is not live-attested.** The lane exists
  behind `ENABLE_GNMI_CORRELATION` but has not been proven end to end on a
  deployment with mutual TLS.
