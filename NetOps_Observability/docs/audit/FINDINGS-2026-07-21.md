**The finding:** every green happy-path test stayed green through all 84
defects, because the defects lived in paths no test entered. Fault injection —
not more assertions on success — is what would have caught this class. The kv
`backend` package var is now an established injection seam; the same pattern
needs applying at the ClickHouse, Kafka, and notification seams.

**CI enforcement — CORRECTED 2026-07-22.** An earlier note here claimed
staticcheck/gosec run only on the crypto packages. That was wrong: `full-lint`
runs **golangci-lint repo-wide and BLOCKING**, and golangci bundles staticcheck
+ gosec, so CLAUDE.md §12 IS enforced tree-wide. Standalone `gosec` reports 117
raw findings, but they are dominated by the rule classes `.golangci.yml`
excludes with cited reasons (G115 protocol byte-narrowing, G703/G704
experimental taint analysis) — not a real gap.

**The real gap was a REGRESSION, caught 2026-07-22:** repo-wide golangci-lint
failed on `nms/retry.go:38` (G404) — introduced by `c587002`'s own F-28 jitter
fix, whose commit message reported "staticcheck clean" from a narrower run.
Fixed with a cited `#nosec`; repo-wide golangci now reports **0 issues**.

**New gate added (`architecture_guards_test.go`):** source-scanning guards that
run inside the already-blocking `go test` — no void `saveLocked()`, no
unchecked save result, no `Sscanf("%d")` int parsing, and `intQuery` must keep
its fail-closed signature. Prose in CLAUDE.md did not stop the class; these
fail the build on the next instance. `kv_paths_test.go` (absolute store keys)
was the first guard in this family.

**New finding, same class (fixed):** `parseIntStrict` was not strict — it used
`fmt.Sscanf("%d")`, which stops at the first non-digit and reports SUCCESS. So
`?limit=1e3` parsed as 1 and `100x` as 100: a different number than the caller
sent, silently. Now `strconv.Atoi`.

**Class insight for the remaining work:** the open bucket is dominated by ONE
class — *accept-and-ignore*: an endpoint returns 2xx for a write it did not
perform, or a filter/limit it did not apply (F-62, F-64, F-67, F-68, F-69,
F-70, F-71, F-73, F-74, F-75, F-77, F-78, F-79, F-80, F-81). Fix the
generator: a write path must return the store's error, and a parsed query
param must fail closed.

## Ingest / storage lane — closed 2026-07-22 (F-03, 05, 07, 08, 10, 11, 14, 49, 58, 59)

Three things from this lane are worth carrying forward:

**F-14 was confirmed by measurement, and the truth was worse than the finding.**
The audit marked it UNCONFIRMED and predicted every dead-letter record would
carry the same constant fallback string. Replayed through the pinned Vector
image (`timberio/vector:0.40.0-alpine`) with a real abort→dropped pipeline:
Vector annotates the event at `.metadata.dropped.{reason,message,component_id}`
in the default (legacy) log namespace, `%vector.dropped.*` is empty, and the
shipped expression `to_string(.metadata.message) ?? "…"` evaluated to **`""`** —
not the fallback, because `to_string(null)` returns `""` rather than erroring,
so the `??` never fired. Every dead-letter document was written with an empty
reason.

**The gap that let these findings exist was an unrun test directory.**
`tests/test_architecture_contract.py` describes itself as the thing that "fails
CI if the finalized wiring is broken" and was in **no workflow**; it had rotted
into a failing state unnoticed. That is now a blocking gate
(`.github/workflows/ingest-contract-ci.yml`) alongside 28 new class guards in
`tests/test_ingest_contract.py`, plus `scripts/vrl-harness.py`, which replays
fixtures through the REAL transform sources lifted out of the live configs —
`vector validate` only ever proved the pipeline COMPILES.

**Two migration hazards were found and handled, not shipped.**
(a) F-58's converge would have deleted 60 days of `findings`/`tunnels` on first
boot: live retention was 90d, the checked-in DDL said 30d, and nothing had ever
enforced 30d anywhere. init.sql now declares 90d and a guard test fails any
default shorter than the declared value. (b) F-08's `${INGEST_TOKEN:?}` makes
Vector refuse to start, which would take the whole ingest tier down on upgrade —
`install.py` seeds the credential into an existing `.env`, the same migration
mechanism used for the Kafka swap.
