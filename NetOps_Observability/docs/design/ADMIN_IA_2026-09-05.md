# Administration information architecture — 2026-09-05

**Owner instruction:** 2026-09-05. **Status:** implemented in `src/frontend/src/nav.tsx`.
**Ratchet:** `src/frontend/src/nav.adminIa.test.ts` (structure + gate table),
`src/frontend/src/nav.legacy.test.ts` (every old hash still resolves).

---

## 1. The rule

There are now **two** governance sections, and the boundary between them is the
**backend route gate**, not the topic of the page:

| Section | Who sees it | Membership rule |
|---|---|---|
| **Administration** (`#/admin/…`) | any `administration:admin` | every route behind the page is `requirePerm` / `requireAdmin` **and tenant-filtered** — the page shows *this tenant's* data |
| **Platform** (`#/platform/…`) | the platform owner only (`platformOnly` on the **section**) | every route behind the page is `requirePlatformAdmin` or `requireCrossTenant` — platform-GLOBAL plumbing (CLAUDE.md §3a rule 3) |

Placing by gate rather than by topic is the whole point. A page whose routes are
tenant-scoped but which is hidden behind a provider-only section is a **function
removed from tenant admins**. A page whose routes are platform-global but which
is offered to a tenant admin is **dead tiles and 403'd saves**. Both are the
same defect seen from opposite ends, and only the gate can tell them apart.

Two mechanical consequences:

* The gate is carried by the **section**, not re-stamped on each leaf. A leaf
  inside Platform must not set `platformOnly` (asserted in the ratchet).
* A provider-level route that the owner deliberately kept inside Administration
  keeps the **leaf-level** stamp. Exactly one leaf does: **Sensors**.

## 3. Decisions taken

1. **The section carries the gate.** `platformOnly` moved from eight individual
   leaves onto one section. A tenant admin no longer sees a half-empty
   Administration list whose gaps are the shape of the platform's plumbing.
2. **Licence opens the Platform section, ungrouped.** It is neither "Security"
   nor a "Tool" — it is the question a provider opens the section to answer, and
   there is one licence file per installation. It is also the section's default
   leaf, so `#/platform` lands there.
3. **Data Collection split into Data sources + Data handling.** The owner asked
   for Sensors under Data sources and for Processors and Sensitive Data Access
   to be one group; a single group could not express both. Telemetry Coverage
   reports on what the *sources* delivered, so it stays with them.
4. **Access Explorer went under Security, not Tools.** The owner listed it in
   both places. It answers "why can this principal reach this?" — a governance
   question, and it belongs beside Sessions and the Audit Log, which answer the
   two neighbouring ones ("who is in right now", "what was done"). Putting it in
   Tools would have separated the three halves of one investigation. It is in
   **Administration → Access & Audit**, not Platform, for the gate reason in §5.2.
5. **Regions and GraphQL Explorer joined Tools.** Neither was named by the
   owner. Both are provider-only surfaces and the owner asked for exactly two
   groups under Platform, so they went to the one that fits: Regions is the
   provider's view of its own region topology, GraphQL Explorer is a
   raw-backend escape hatch.
6. **The "Platform Security" group name is retired.** Its provider half became
   `Platform → Security`; its tenant half became `Administration → Access &
   Audit`, a name that says what the four pages do rather than who owns them.
7. **Nothing changed about any page's behaviour.** Every leaf kept its id, its
   `render`, its lazy chunk and its server gate. The only visibility change is
   Sessions, which stops being hidden from the tenant admins whose own sessions
   it lists (§5 item 7 in the table above).

## 4. Redirects

`LEGACY_ROUTE_ALIAS` in `nav.tsx` gains one entry per moved leaf, so every
bookmark, saved landing, `⌘K` history entry and panel drill keeps resolving:

```
admin/auth → platform/auth                admin/health     → platform/health
admin/data-protection → platform/…        admin/grafana    → platform/grafana
admin/licence → platform/licence          admin/opensearch → platform/opensearch
admin/regions → platform/regions          admin/graphql    → platform/graphql
stack → platform/health   (LEGACY_SECTION_ALIAS: stack → platform)
```

`explain → admin/access` is unchanged: Access Explorer did not move.

`aliasSegs` gained a **three-segment** exact key, tried before the two-segment
one, so a route that names its group as well as its leaf maps onto the real
section/leaf pair instead of being read as leaf `tools` plus an in-page
sub-item:

```
platform/tools/pipeline-debugger → platform/pipeline-debugger
platform/tools                   → platform/health
```

The two-part `#/section/leaf` router has no room for a group segment; aliasing
is how the agreed route id `platform/tools/pipeline-debugger` still lands on the
debugger instead of falling back to the section's first page. The leaf's own
canonical route is `#/platform/pipeline-debugger`; both resolve to the same page
and `canonicalHash` rewrites the first onto the second.

## 5. Where the gate contradicts the owner's placement

Five items. In each the gate was read from the handler, not from a comment.

### 5.1 Licence — owner said tenant-level; the gate is provider-only

> Owner: "Licence (tenant level — show the tenant its entitlements/usage/
> ceilings; the upload/replace action stays visible to the provider only)."

`/api/system/licence` is registered **once** (`main.go:2616`) and the gate runs
**before** the method switch:

```go
// internal/licence/api.go
caller, ok := a.d.Gate(w, r)   // :183 — main.go:4764 licenceGate → requirePlatformAdmin
if !ok { return }
switch r.Method {
case http.MethodGet:    a.writeJSON(w, http.StatusOK, a.view(r.Context()))
case http.MethodPut:    a.install(w, r, caller)
case http.MethodDelete: a.remove(w, r, caller)
```

`licence_routes_test.go:761-765` asserts all three verbs answer **403** to a
tenant admin. There is no other licence read route: `/api/features`
(`main.go:3291`) returns env feature flags, not licence terms, and
`licenceFeature` (`main.go:4850`) only produces a 402 refusal body on four
gated routes.

**Placement: Platform.** Moving the page to Administration without a backend
change would ship a page that 403s for every principal it was moved for. The
page's own read-only branch (`canEdit=false`) is therefore currently
unreachable; it is kept and its wording sharpened, and the file says so.

**To honour the owner's intent, the backend must first** split `GET` onto
`requireAdmin` and return a tenant projection (entitlements · usage · ceilings ·
features; no `licence_id`, no install/remove controls, no key material), leaving
`PUT`/`DELETE` on `requirePlatformAdmin`. That is a backend change and is out of
this change's scope.

### 5.2 Access Explorer — owner put it under Platform; the gate is tenant-level

```go
// access_explain.go:115
claims, ok := s.requireAdmin(w, r)
...
if target == "" { target = strings.ToLower(claims.Sub) }   // default: explain myself
if !s.canExplainPrincipal(claims, target) { /* empty map, not 403 */ }
```

`requireAdmin`, scoped by `canExplainPrincipal` to principals the caller's own
org administers. It is a tenant-admin page by construction — its default answer
is "explain me". `nav.test.ts` already carried the assertion *"Access Explorer
is per-tenant (not platform-only) — still reachable"*.

**Placement: Administration → Access & Audit.** Putting it under a provider-only
section would take a working page away from every tenant admin, which the
owner's own rule for the Platform section forbids ("Any tenant-level item
currently under Platform moves out").

### 5.3 Transport Security — owner put it under Platform; the view is tenant-level

```go
// main.go:2886  /api/security/transport-posture
claims, ok := s.requireAdmin(w, r)
// main.go:2935  /api/security/transport-posture/export
claims, ok := s.requirePlatformAdmin(w, r)
```

Only the **export** is provider-level; the inventory itself is `requireAdmin`
and device-lane scoped. The nav comment shipped with SEC-021.1 says the same:
*"NOT platformOnly — tenant admins get their scoped device-lane view."*

**Placement: Administration → Access & Audit.** Same reason as §5.2.

### 5.4 Telemetry Coverage — owner asked us to verify; verified, tenant-level

`/api/telemetry/unrecognized` is `requirePerm(infrastructure, read)` and
tenant-filtered — the tenant's own unrecognized message shapes. Only
`/api/admin/parser/stats` is `requirePlatformAdmin`, and the page already renders
a "platform-admin only" card for it rather than dead tiles. **Stays tenant-level.**

### 5.5 Notifications — a real mixed page, left where it is

Channel configuration (`/api/notify/{smtp,slack,pagerduty,…}`) is
`requirePlatformAdmin` (`notify_config.go:414`); contact points are
`requireAdmin` (`contactpoints.go:43/56`). The tenant half is the operator
surface and the platform half already refuses a tenant admin at the route, so the
page stays in Administration. **Flagged, not moved** — splitting it is a page
change, not an IA change, and the owner did not ask for one.

### 5.6 GraphQL Explorer — the UI is stricter than the route

`graphql.go:84` gates `/api/graphql` with `requirePerm(infrastructure, read)`,
which a tenant admin holds; the nav leaf has been provider-only since it was a
Stack page. Keeping it provider-only under Platform → Tools preserves today's
behaviour and errs **fail-closed**. Unhiding it would be a new exposure and was
not asked for. **Flagged for a decision, not changed.**
