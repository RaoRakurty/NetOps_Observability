## 4. Where the time goes now (the P2 brief)
1. **The load epoch is the whole story.** Sampler rows: from 19:32 to at least
   19:53 the cohort counter sat at **4** and pending was flat at **35,053** while
   `corr_engine_epoch_seconds_max` reached **3,881 s** — one epoch = 20 cohorts ×
   ~190 s. During that epoch: components 14,605, touched 3,566, memo hits 2,098
   (**14 %**), ranked **12,507**. So **8,941 UNTOUCHED components (61 % of the
   epoch's evaluations) were fully ranked because they were first seen in that
   epoch** — the memo is intra-epoch by design (P1 §2: nodes are rebuilt after
   prune, so a cross-epoch key must be content-addressed). The 74 % overall hit
   rate is earned in the tail epochs that re-see the same components; it is not
   the rate that matters for TTUR.
2. Per-cohort cost ≈190 s is engine compute (GIL-bound Python), not ClickHouse:
   all corr_* inserts in the window sum to 17.5 % of wall.
3. A 65-minute epoch defers retention prune and the (now epoch-cadence)
   merge/quiesce/cap passes by 65 minutes and holds `oldest_pending_age` at 710 s
   (> the 516 s horizon) for the whole time. Epoch length needs a wall-time /
   cohort budget — the 20-cohort cap was set when a cohort cost seconds.
4. `material` digest cache hit rate is 0: the object is re-materialized per
   version, so the per-instance cache never serves a second read. The saving P1
   §3 got was the content-hash path (69 % cached) and the single blob build.

Implication for P2 (Decision/Evidence split, owner memo §14–15): the biggest
remaining redundant term is **re-ranking unchanged components across epochs**,
i.e. exactly the "content-addressed quantum" the research synthesis calls for —
a decision memo keyed by the component's canonical input identity (node signal
ids + carried-edge identity + catalog/topology/policy versions) that survives
epochs; and the Evidence-plane deferral of the ~4 child-row inserts + archive
slice per version so the Decision-plane verdict lands first. Spec:
`docs/design/DECISION_EVIDENCE_SPLIT_P2_2026-08-28.md`.

## 5. Equivalence review (owner memo §23–25) — `P1_2P5K_EQUIVALENCE_2026-08-28.md`
### 5.1 Differences, explained
- **Storm aggregate object**: `agg_cid = uuid5(SIGNAL_NS, "corrobj|<tenant>|storm-noise")`
  (engine.py ~2910) is tenant-constant, so BOTH legs wrote the same cid
  (`bb1e46d6…`, OLD v1–15, NEW v1–16, node_count peak 6,005 → final 378). A
  naive per-leg scope attributed it to OLD only. Not a regression; excluded
  from the table by cid. Every other undetermined object in both legs is a
  1-node singleton.
- **Merges 11 → 378**: all 378 satisfy `find_merges` on the persisted rows
  (window overlap 378/378, Jaccard ≥ 0.4 min 0.400 / median 0.429, shared
  entity AND device 378/378, same top_hypothesis 378/378, no cycles, chain depth
  ≤ 2). The mechanism is NOT "the epoch pass sees more pairs" (set-inclusion
  shows the epoch pair space is a subset of the union of cohort pair spaces).
  Inferred mechanism: pre-P1 quiesce + the 163 cap ran after EVERY cohort and
  deleted stale candidates before the cohort carrying their live survivor ran;
  with epoch cadence the cap fired twice in the whole run. **Correctness
  improvement, small magnitude.** Same mechanism explains fewer cids (mean
  node_count 3.00 → 3.41; 29,929 identity adoptions logged in NEW): the
  −1,284 incidents are not decomposed quantitatively.
- **Undetermined 1,206 → 1,319 (+112, 27 non-storm / 85 storm): unexplained.**
  Carried as an open item (tracker 176 follow-up) — not blocking, since owner /
  tier / confidence equivalence holds on matched incidents (§5.3).
### 5.2 Uncontrolled variables
Storm mode was declared on 100 % of OLD objects vs 93.5 % of NEW (the faster
engine held the buffer under the storm threshold for part of the run); onboard
slowdown (API side); the NEW leg's harness interrupt (no memflat reading; no
gate verdict). The next A/B must run to the completion gate with the stage
profiler on.
### 5.3 Review outcome
200 incidents matched on (normalized device set, top_hypothesis): **owner 100 %,
verdict_tier 100 %, top_confidence 100 %, node_count 96.5 %**. The non-circular
device-set-only match (39 one-to-one keys): hypothesis 37/39, tier 39/39, and
both mismatches are NEW objects that grew (3→8, 3→9 nodes) and re-ranked — the
intended direction. No unrelated-incident merge found; no lost incident found.
**P1 passes the equivalence review; commit.**
