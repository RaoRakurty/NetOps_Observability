# July 2026

## New features

### Canonical incident report

An incident document rendered on the server from the same tenant-scoped slice as
the timeline, available as JSON, HTML or PDF. It carries four independent
states: incident (active, recovering, recovered, closed), analysis (observed,
suspected, probable, confirmed, inconclusive), impact, and ticket.

**Only a confirmed analysis may title itself "Root Cause Analysis."** The PDF is
rendered through a controlled path with its own header and footer, so browser
print furniture never appears in a customer-facing document.

- **API:** `GET /api/correlations/{id}/rca-report`
- **Read next:** [Read an RCA case](/investigate/read-an-rca-case)

### Postmortem layout and immutability

The report became a twelve-section postmortem: causal chain, detailed timeline,
glossary, impact provenance, detection milestones, artifact classes and a
structured action-item register. Reports are immutable. An integrity block plus
a tenant-scoped revision register makes a regenerated report reproducible byte
for byte, and tampering detectable.

### Reports are written for real outages only

The HTML and PDF document renders only for a **promoted** case. The JSON and
workspace view stay readable for every candidate. Automatic promotion requires
all four of: a production incident rather than a validation scenario, a
confirmed verdict, confirmed user or application impact, and a duration of at
least two minutes. Anything else needs an audited manual promotion.

- **API:** `POST|DELETE /api/correlations/{id}/rca-promotion`,
  `GET /api/correlations/rca-reports`

### Seam ownership on every case

Engine attribution replaced a hardcoded owner. Each case names the **seam** that
owns the fault and, through a per-tenant ownership registry, the party
responsible for it.

- **API:** `/api/settings/seam-owners`
- **Read next:** [Glossary](/reference/glossary)

### The causality path leads the report

"Incident at a glance" opens the report: where, what possibly happened, the
possible owners, and a causality path drawn with the break in red. The drop
point is stamped by the engine and gated on the verdict, so the break is earned
rather than decorative.

Correlix states a cause it can support. When the evidence supports a likely
cause but not a confirmed one, the report says "possibly because of" and names
the evidence state. That is the intended behaviour, not a gap.

### Active verification

On a suspected open case, Correlix can run a closed read-only command battery
against the implicated devices and feed the answer back as its own evidence
modality, corroborating or refuting the hypothesis. The device's own answer
counts as an independent source against a probe or a flow, while observer
identity still prevents a device from corroborating its own passive telemetry.

- **Flag:** `FEATURE_ACTIVE_VERIFICATION`, default off, plus a per-tenant opt-in
- **API:** `POST|GET /api/correlations/{id}/verify`, `GET|PUT /api/settings/verification`

### Alert episodes

Active Alerts renders **episodes** rather than a flat firing dump: one row per
episode with an occurrence count, Active, Cleared or Closed state, Flapping and
paused or snoozed chips, first and last seen, and a triage panel with
acknowledge, assign, mute, snooze, a note trail and a pivot to the logs.

- **API:** `/api/alerts/episodes`, `…/{id}/ack|assign|mute|snooze|note`
- **Read next:** [Manage alerts](/monitoring/manage-alerts)

### Maintenance windows

One-shot or recurring windows, timezone-aware, scoped by device, site or rule.
Planned work stops paging **and** stops polluting reliability statistics:
incidents whose onset fell inside a covering window are stamped as maintenance
and excluded from the mean-time calculations.

Two behaviours to know. Alerts stay visible; only notifications are suppressed.
And suppression **fails open** on a store error: noisy beats silently dark.

- **Where:** Operations → Maintenance Windows
- **API:** `GET|POST /api/alerts/maintenance-windows`, `GET|PUT|DELETE …/{id}`

### Ticketing driven by RCA, not by raw alerts

ServiceNow, PagerDuty, Slack and Jira each became a tenant-scoped incident
destination keyed on a stable identity derived from the correlation object. A
57-alert storm produces one incident, not 57 tickets. PagerDuty incidents close
automatically when the alerts clear.

- **Read next:** [Ticketing and automation](/incident-response/rca-ticketing)

### Real SNMP subnet discovery

The scanner is bounded: 4,096 hosts total, 32 workers, a 2-second probe budget
per host, a 60-second cooldown. It is RFC 1918 by default; public address space
needs an explicit allowance. Community strings are a priority list, sealed and
write-only.

**The shipped `10.0.0.0/8` default is refused with a clear error rather than
swept.** Narrow it before you point Correlix at a real network.

- **Flag:** `ENABLE_SNMP_DISCOVERY`
- **API:** `GET|PUT /api/discovery/config`
- **Read next:** [Configure SNMP discovery](/onboard-devices/snmp-discovery)

### SNMP configuration generator

One call produces the device CLI to paste and provisions the matching profile at
the same time.

- **API:** `/api/onboard/snmp-config`
- **Read next:** [Vendor SNMP configuration](/onboard-devices/vendor-snmp-configs)

### Vendor controller integrations

A vendor-neutral framework that ingests a controller's **intelligence**
(metrics, state and events) rather than its logs. It covers a connector
registry, authentication, pollers, webhook intake, checkpointing, rate limiting,
retry with backoff and jitter, and a producer that turns a controller event into
a correlation signal.

- **Flag:** `FEATURE_NMS_INTEGRATIONS`, default on. The runtime is read-only and
  inert until you connect a controller.
- **API:** `/api/nms/connectors`, `/api/nms/integrations`, `…/{id}/poll`,
  `/api/nms/webhook`
- **Read next:** [NMS integrations](/infrastructure/nms-integrations)

### Interfaces and optics

A universal transceiver-diagnostics collector with per-vendor adapters, a
deterministic port-health score, a physical-layer event producer, and 23
physical-layer failure signatures. The workbench ships six operator column
presets and a detail drawer that separates logical interface state from physical
transceiver state.

- **Flag:** `FEATURE_PORT_DOM`, default off, for transceiver diagnostics
- **Where:** Infrastructure → Interfaces & Optics

### Wireless

A vendor-neutral wireless model covering controllers, access points with uplink
columns, slot-keyed radios, and SSIDs, WLANs and BSSIDs as separate identities,
with read-only ingestion, sessions and onboarding episodes, correlation
integration and a wireless module for Iris. Controllers and access points appear
in the device inventory as fleet citizens.

The remediation framework has five gates and all of them fail closed. Version 1
registers no executor at all, so an attempted action records a failure and a
reason rather than pretending to have run.

- **Flag:** `FEATURE_WIRELESS_ACTIONS`, default off
- **Retention:** `CH_WIRELESS_RETENTION_DAYS`, 30 days. No per-client series
  reaches the metric store; that is enforced by the schema.

### Cloud observability

A provider registry and a seven-step onboarding wizard front AWS, Azure and GCP:
catalog, draft, authentication, trust templates, scopes, validation with
findings, and activation. Credentials are keyless where the provider supports
it. **Activation is gated on a real validation result, not on optimism.**

The Cloud Data Sources page separates two questions that are usually conflated:
connection health (identity) and data delivery (telemetry). A connector whose
identity works but whose telemetry is silent shows as a red "Connected, no data
arriving" row that sorts first.

Also shipped: cloud inventory and topology discovery, an observed service
dependency map, cloud logs on seven filterable lanes, per-tenant service-level
objectives that read "not measurable" with a reason when there is nothing to
measure, a daily cost lane surfaced as context on an investigation, and
per-tenant monitors.

- **Flag:** `FEATURE_CLOUD_SIGNAL_NOTIFICATIONS`, default off, routes cloud RCA
  objects to the owning tenant's own channels

### Pipeline processors

A per-tenant data-shaping editor where every matcher and action defines its
validation and both of its evaluators in one place, so the dry-run preview and
the live pipeline cannot drift apart. Actions include mask, drop with a required
guard, and configurable replacement tokens. Versioned, with fail-safe rollback
and hot reload.

- **Flag:** `FEATURE_PROCESSORS`, default on
- **Where:** Administration → Processors

### Sensitive data scanner

Sixteen curated, versioned, read-only detectors covering email, IPv4, IPv6, MAC,
US SSN, phone, credit card, IBAN, JWT, AWS access key, private key, SNMP
community, secret in text, password field, bearer token and basic-auth URL.

Three actions. **Hash** produces a stable digest that is unreadable but still
joinable. **Tag** detects and changes nothing, so you can roll out safely.
**Redact keys** removes named keys. A field of `*` sweeps every string in the
event recursively while preserving the pipeline's own tenancy, time and routing
fields.

### Sealed fields

Reversible field-level encryption at the edge, with versioned per-tenant keys,
parity between the ingest and application ciphers, a role-gated and audited
reveal path, and key rotation that never orphans data.

The Sensitive Data Access page is the compliance read-back. It shows
**refusals as well as successes**, and it can never display a revealed value,
because the server records no plaintext.

- **Flag:** `FEATURE_SEALED_FIELDS`, default off. Sealing also requires real key
  material.
- **Where:** Administration → Sensitive Data Access

### One-command appliance installer

Extract the bundle, run `./install-correlix.sh`, open the printed URL. It runs a
host preflight, verifies checksums, joins split archive parts, waits for health
and prints the credentials, with readable failure text rather than a stack
trace. Subcommands: `status`, `logs`, `stop`, `start`, `uninstall`,
`reset-demo-data`.

- **Read next:** [Install Correlix on a Linux host](/deploy/install-linux)

### Host-sized installs

A resource planner detects the host and sizes the stack by default across demo,
small, medium, large and custom profiles, deriving each component's internal
limits from its own container boundary. **It refuses a plan it cannot honestly
fit rather than oversubscribing the host.**

- **Read next:** [Plan host resources](/deploy/sizing)

### Data protection

The backup destination and schedule became first-class configuration with live
status: whether a repository is registered, how old the newest snapshot is,
whether the only copy is on this host, and the result of the last restore drill.
**A schedule with no off-host destination is refused with a `400`** — a
local-only nightly backup fills the disk it exists to protect.

- **API:** `GET|PUT /api/system/backup`
- **Where:** Settings → Data Protection

### Iris

The in-app assistant answers questions about your network and about Correlix
itself, grounded in a curated concept knowledge base and in this documentation,
and cites the page and section it answered from. A verifier, an evaluation
suite, a model router and a feedback loop back it. Per-tenant entitlement and a
bring-your-own provider key, sealed under the tenant key, arrived with it.

- **Flags:** `FEATURE_AI`, master switch; `FEATURE_AI_TOOLS`, default off, for
  the bounded tool loop
- **API:** `/api/ai/ask`, `/api/ai/tenant-config`, `/api/ai/tenants`,
  `/api/ai/feedback`
- **Read next:** [Iris](/iris-ai/overview)

### One tenant at a time

Cross-tenant reach stopped meaning cross-tenant display. A cross-tenant
principal with no acting scope gets an organization and tenant picker instead of
merged rows, and the choice follows every page, query and export. Single-tenant
principals are never gated. There is deliberately no "all tenants" telemetry
view.

- **Read next:** [Tenants and organizations](/administration/tenants-orgs)

### Unified search and permanent resource pages

`GET /api/search?q=` resolves a name, an id or an address to typed, linkable
results across devices, cloud resources, applications, connector accounts and
correlation cases, ranked exact before prefix before substring, backed by
permanent resource pages and a search-first top bar.

### This documentation portal

The portal is served from the product at `/docs/` and embedded as a Help drawer
behind the question-mark button. A missing page returns a real `404` rather than
a `200` fallback.

## Changes

- **Apache Kafka replaced Redpanda**, and Valkey replaced Redis, both for
  licensing reasons. The bundle build fails if a Redpanda image is present.
- **Prometheus was removed.** VictoriaMetrics self-scrapes.
- **The assistant was renamed** from Correlix AI to **Iris**.
- **Theme selection moved to sign-in** and to the account menu. The top-bar
  light and dark control was removed.
- **The legacy raw-alert to ticketing lane was removed.** Ticketing is driven by
  RCA policy. `FEATURE_LEGACY_ALERT_ITSM` re-enables the old path.
- **Accessibility** reached WCAG AA across the shell, forms, tables, dialogs,
  dashboards and the RCA workspace.
