# August 2026

## New features

### TLS and mTLS on every internal hop

A fresh install can now bring up the whole stack on authenticated, encrypted
transport. The installer asks one question and configures the rest: Kafka
secure listeners with an enforced ACL matrix and no plaintext listener, the
search tier with its security plugin enabled, ClickHouse over TLS, PostgreSQL at
`sslmode=verify-full` refusing plaintext TCP, VictoriaMetrics behind an
authenticating proxy, the cache tier authenticated over verified TLS, mutual TLS
between the web tier and the API, the Kafka controller listener on mutual TLS,
per-lane ingest credentials on the four ingest lanes, and a workload-identity
registry that issues an identity to every service.

- **Where:** `python3 scripts/install.py --tls yes`
- **Read next:** [Enable TLS and mTLS](/deploy/enable-tls)

### Transport Security page

A read-only posture view that joins the declared transport inventory, a probe of
the certificate actually served on each hop, and the workload identity presented.
Drift means one of three things: TLS is declared but no certificate is on the
wire, the certificate on the wire has expired, or a certificate is ahead of what
was declared. **A hop that was not probed says so.** The view exports as a
report.

- **Where:** Administration → Transport Security
- **API:** `/api/security/transport-posture`, `…/export`
- **Read next:** [Review transport security posture](/security/transport-security)

### Certificate rotation hardening

Reissue runs on a need-based daily sweep with jitter. Expiry is watched **on the
wire**, not on disk, so a certificate that was replaced on disk but never
reloaded is still caught. A quorum-certificate expiry watch and a dead-man alert
back it up.

### Production security validator

A boot-time validator that fails closed, with no global bypass, and publishes
its finding counts as a metric queryable for the life of the process. Posture
drift raises alerts on the same vocabulary.

### Eight-section navigation

The console was re-mapped to Overview, Operations, Investigate, Infrastructure,
Explore, Security, Analytics and Administration, with every surface on a real
route. New routed pages: Action Queue, Sites, Discovery and NMS, and a Logs
Explore shell.

Every deep link saved before the redesign still resolves. A 58-entry exact
alias table plus 9 section aliases preserve suffixes and query strings, and a
149-assertion check fails the build if a future change orphans a saved link.

Renames: Correlations became **RCA**, Collectors became **Sensors**, WAN
Interface Metrics became **WAN Paths**, Vulnerability Management became
**Vulnerabilities**, RCA Auto-Ticketing became **Ticketing & Automation**.

### Graphical installer

A guided setup console covering readiness, host preparation, deployment,
discovery, sizing, security, review, install and launch. It serves over TLS with
a printed certificate fingerprint, binds to localhost unless you opt into
`--remote`, holds a single session with a 15-minute idle timeout and automatic
shutdown, passes the sudo password over TLS to child stdin and then zeroes it,
and produces a sanitised support bundle.

On the engine side, `install.py` gained `--progress-json` with 14 contract stage
markers, `--snmp-discovery CIDR[,CIDR]` and `--bootstrap-docker`.

- **Read next:** [Install Correlix on a Linux host](/deploy/install-linux)

### Identity providers configured from the console

You no longer touch the identity broker's own console or its scripts. The SSO
panel accepts SAML metadata by URL, paste or upload, with a signing-certificate
expiry banner; OIDC by discovery with a write-only client secret; attribute
mappings; and an ordered group-to-role table where the first match wins. Saving
reconciles the realm, client, provider and mappers through the broker's admin
API. If the broker is down, the save persists and answers `502` with a re-apply
warning rather than losing your input.

Sign-in hardening: PKCE with S256, a nonce, and single-use SSO login
transactions.

- **Where:** Administration → Authentication → SSO
- **API:** `/api/auth/sso/idp`, `…/{alias}`, `…/{alias}/test`
- **Read next:** [Authentication](/administration/authentication)

### BGP Operations page

A one-screen prefix-outage view: a verdict hero with announced state, origin,
visibility percentage and RPKI chips; AS-path pills grouped by prevalence with
prepending compressed; an hourly announce and withdraw churn strip; a registry
ownership card; and watchlist chips. **Every panel fails independently and says
so.**

The tenant watchlist lives in PostgreSQL with row-level security, and the owner
is stamped from the security context, never from the request body.

- **Where:** Analytics → BGP Operations
- **API:** `/api/bgp/watchlist`, `/api/bgp/resource`
- **Read next:** [Investigate a BGP prefix](/bgp/investigate-a-prefix)

### Snapshot policy control plane

The Backup and Data Protection page became a view over the search tier's own
snapshot-management policy, mirroring its vocabulary rather than inventing a
parallel one: `enabled`, a cron `schedule`, `retention.max_count` and
`max_age_days`, plus last-run status, duration and the next trigger. **A
scheduled backup with no run report reads "never ran / not reporting", never
blank.**

- **API:** `GET|PUT /api/system/backup/snapshots`
- **Read next:** [Back up and restore](/deploy/back-up-and-restore)

### The stack watchdog ships to customers

The external watchdog is now in customer bundles, and the setup wizard's success
screen enables it. It runs outside the stack on purpose: a notifier inside the
stack cannot report the stack's own death. Channels beyond a bare public topic:
a self-hosted authenticated push service, email forwarding, a dead-man's-switch
ping, and an authenticated JSON webhook on every up-to-down and down-to-up
transition.

### Event isolation for events that cannot be sealed

An event that cannot be sealed is quarantined rather than passed through.
Quarantine isolation is enforced at every boundary, attribution is preserved,
and an operator workflow exists to review and reattribute.

- **API:** `/api/quarantine`, `/api/quarantine/reattribute`

### Correlation scales horizontally

The correlation engine was a single loop over one multi-topic consumer. It now
scales by co-partitioned tenant slices: producers key each record by the
attributing tenant, topics are created at `BUS_PARTITIONS` and only ever
increased, and the consumer pins an assignor that keeps a tenant's topics
together.

Storm mode arrived with it, along with ingest-priority scheduling, a bounded
cohort scheduler, a cap on open objects with defined behaviour at the bound, and
retention that runs on stream time per tenant.

- **Read next:** [Reference capacity](/deploy/reference-capacity)

## Changes

- **CTEM foundations.** The building blocks the September Security section
  renders: an owned normalised finding model, a vendor-advisory provider seam, a
  compliance lane, a network-device hardening rule engine, a MITRE-tagged threat
  lane, and a bus seam that turns a finding into a generic evidence event.
- **A third security remediation pass** hardened shipped surfaces: escaping in
  every chart tooltip, a one-time WebSocket ticket replacing a session token in
  a URL for device SSH, SNMPv3 poll responses verified before engine state is
  trusted or a response is decrypted, SNMP trust-boundary hardening against trap
  forgery, and a closed path to platform-owner self-elevation over a bearer
  token.
- **The topology minimap was removed.** Domain and density are dropdowns on the
  toolbar, and the canvas is full-bleed.
