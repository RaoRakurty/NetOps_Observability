# November 2026

## New features

### Iris understands a question however it is asked

With the Iris AI add-on on, one quick model call reads each new question and
picks the answer path, so a question no longer has to match a fixed phrasing.
Questions Iris could not answer are grouped by reason for an administrator to
review, and your team's own names can be taught to Iris. If one model fails,
Iris tries another and otherwise shows the evidence answer with a note.

- **Where:** the Iris panel; **AI models** → **Iris vocabulary**
- **Flag:** **Iris AI models** (Features page; needs the Iris AI add-on)
- **Read next:** [Iris](/iris-ai/overview), [Teach Iris your names](/iris-ai/iris-settings)

### The Iris AI add-on

Model-backed Iris — written answers, model chat and AI investigations — is the
`iris_model` licence add-on. Enterprise includes it. Evidence-only Iris, which
answers from Correlix's own data, stays free in every edition. The Iris switches
are set on the Features page only.

- **Where:** Platform → Configuration → Features, section **Iris AI**
- **Read next:** [Set up Iris](/iris-ai/setup)

### 25 troubleshooting methods, applied to your network

Iris gained methods for platform health, clock synchronisation, QoS congestion,
SD-WAN overlays, tunnels and VPNs, layer-3 reachability, DNS, EVPN/VXLAN,
first-hop redundancy and link aggregation, scope contrast and design reading. A
method now runs only where it fits the device Correlix discovered — for example,
the OSPF method on a device with OSPF — and says what it could not establish.
Iris can now read IPsec security associations and IKE state from a device, and
explain the whole network's topology.

- **Read next:** [Iris skills and chaining](/iris-ai/skills)

### Investigations

The read-only Investigator works a problem through in steps, starting from the
correlation engine's verdict and your own runbooks. Investigations can start on
their own on a matching new incident or a schedule, and an optional switch lets
Iris's methods send a short test (ping, traceroute, DNS or web) from Correlix's
own server.

- **Flag:** **AI investigations**, **Iris active probes**
- **Read next:** [Investigations](/iris-ai/investigations)

### Change assistance, read-only

Iris reviews a change plan against a checklist and your network, checks whether
a device is ready to upgrade, shows vendor upgrade procedures you can adopt as
MOPs, and compares a device before and after a change from the device page's
**Change** tab. Iris never changes a device.

- **Read next:** [Change assistance](/iris-ai/change-assistance)

### Seasonal answers

Ask "is this normal for this time of week?" and Iris compares the value with the
same hour in earlier weeks, or earlier days when weeks are not there yet.

- **Flag:** **Seasonal baselines history** (`FEATURE_SEASONAL_ROLLUP`, optional)
- **Read next:** [Seasonal answers](/iris-ai/seasonal-answers)

### Fixes, runbooks and learning

Record how a case was fixed, and see "last time this was fixed by…" on similar
incidents. Workspaces write their own runbooks and MOPs with two-person
approval; Iris proposes facts and runbook drafts from recorded fixes, and a
person decides. Iris can propose an ITSM ticket note or a memory entry, sent
only after a second person approves.

- **Read next:** [Fixes and similar incidents](/iris-ai/resolutions),
  [Runbooks and MOPs](/administration/iris-runbooks),
  [Iris learning](/administration/iris-learning),
  [Approve Iris actions](/administration/iris-actions)

### Iris in Slack and Teams, and over MCP

People can ask Iris from Slack or Microsoft Teams, as their own linked accounts.
An external AI assistant can use Iris's read-only lookups over the Model
Context Protocol with a workspace API key.

- **Flag:** **Iris in Slack and Teams**, **Iris over MCP (read-only)**
- **Read next:** [Iris in Slack and Teams](/administration/iris-chat),
  [Iris over MCP](/administration/iris-mcp)

### Flows: links, capacity and per-interface views

The Flows page shows traffic per link, with what changed on each link, and a
Capacity tab with the 95th percentile, peak, headroom and when a link reaches
90 %. Per-interface roll-ups, flow duration and per-exporter declared sampling
make the numbers exact.

- **Read next:** [Analyse flows](/explore/flows)

## Improvements

- **Routine management sessions** (monitoring polls, controller sessions) are
  hidden on the Logs page by default and counted. Their individual records are
  kept for 96 hours, and a per-minute summary for the full log retention, which
  cuts their storage sharply.
- The Overview capacity outlook uses the same calculation as the Flows
  Capacity tab.
- Correlix proves the monitored devices themselves are reporting, not only that
  the pipeline runs, and pages when they go silent.
- New syslog packs: HPE Comware and Dell DNOS 6.
- An SNMP community string is never stored.

## Fixes

- A bad time-window parameter now returns an error instead of silently showing
  the last hour.
- Discovery records left behind when a scan range changed now age out instead
  of staying as live duplicates.
- The interface parser no longer reads an SSH "connection closed" line as an
  interface.
